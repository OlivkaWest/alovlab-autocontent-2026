## 5. Контент-движок (рубрики и пропорция)

Не пишем посты по одному. Крутим повторяемые рубрики — это и есть конвейер.
Четыре опоры, здоровая пропорция на неделю **2 : 1 : 1 : 1**:

| Опора | Что делает | Доля |
|---|---|---|
| Польза | приём, разбор, инструкция — результат зрителю | 2 |
| Смысл / позиция | взгляд Ильи: как надо и как нет — доверие | 1 |
| Практика / кейс | что реально вышло в работе, с деталью — доказательство | 1 |
| Приглашение | мягкий шаг: гайд, интенсив, бриф — не чаще 1 на 3–4 | 1 |

Базовые рубрики под проверенный формат:
- **«ИИ сделал сам»** — демонстрация результата + метод (ядро, приоритет).
- **«Дело не в модели»** — почему у новичка выходит дёшево, и что решает на самом деле.
- **«Связка недели»** — узкий разбор одной рабочей связки инструментов.
- **«Не бойся инструмента»** — спокойная провокация про замену/страх ИИ (голос Нейромонаха).

### Reels / короткое видео — по секундам (удержание решает всё)
- **0–2 сек — крючок.** Кадр или фраза, после которой нельзя пролистнуть. Без «привет, друзья».
- **2–8 сек — проблема.** Назови боль конкретно.
- **8–25 сек — один приём.** Ровно один. Показать, а не рассказать.
- **25–35 сек — результат.** Что меняется, если применить.
- **финал — CTA.** Одной строкой, спокойно: «забирай в комментариях под постом» за конкретным (TG + ВК).

Сценарий пиши двумя колонками: **что говорим** (закадр/реплика) и **что в кадре**
(действие + текст на экране).

> **⚡ HeyGen + Seedance — жёсткое правило: см. Приложение Г.** Каждую сцену делим на `avatar_scene`
> и `non_avatar_scene`; сцены без аватара ОБЯЗАТЕЛЬНО генерируются через Seedance внутри HeyGen как
> motion-сцены (не картинка / не скриншот / не overlay / не slideshow / не зум).

### Пост (Telegram / VK)
Хук → ситуация → одна сильная мысль → пример из практики → как применить сегодня → естественный призыв. 800–1500 знаков.

### Подпись к посту / карусели / Reels (описание в ленте) — держим коротко
Инстаграм обрезает длинное на «…ещё», и до CTA не дочитывают. Поэтому:
хук в первой строке (первое слово уже работает), одна мысль, до призыва — без воды.
Ориентир длины: **B2B/B2C-описание — до ~500 знаков, Reels-подпись — 300–400**.
Никаких вступлений и разгона: не «в этом посте», не пересказ карусели — только зацеп и выход.
CTA — одной строкой: «забирай в комментариях под постом» (работает в TG и ВК); B2B-бриф → @alovlab.

### Продающий текст
Контекст → проблема → гипотеза → решение → простой следующий шаг.
Не дави. Не начинай с рассказа об AlovLab — начни с задачи клиента.

### Карусель (4:5)
Слайд 1 — хук + обещание. Слайды 2–N — одна мысль на слайд. Последний — вывод + призыв,
логотип преимущественно на последнем слайде. Держи 5–8 слайдов.

## Приложение Б. Карусели (обязательное правило)

> **⚡ С 19.08.2026 действует НОВАЯ визуальная система — `content/carousels/VISUAL-SYSTEM.md`.**
> Карусель = сильная типографика (верх 35–45%) + смысловой фотореал-кинокадр (низ 55–65%),
> у каждого слайда — свой bespoke image-prompt. НЕ схемы/иконки/пустые карточки в нижнем визуале.
> Перед сборкой финала — концепт по слайдам (SLIDE / VISUAL METAPHOR / SCENE / IMAGE PROMPT / LAYOUT)

Премиальная карусель = **6 слайдов, один пост**, порядок:
`1 обложка → 2 провокация → 3 связка → 4 неделя → 5 пик → 6 CTA`.
Каждая карусель разбирает пользу ИИ в **конкретном бизнесе**; ниши **не повторяются**.

Пайплайн и шаблон — `content/carousels/README.md`, скрипты
`scripts/carousel_render.py` (+ `scripts/carousel_shoot.js`). Новый бизнес = запись в `CONFIGS`.

## Приложение В. Методички / гайды (премиум-PDF) — обязательное правило

> **⚡⚡ GLOBAL METHODOLOGY RULE (высший приоритет для методичек/каруселей/рилсов как системы):**
> `content/rules/GLOBAL-METHODOLOGY-RULE.md`. Ключевое: методичка = самостоятельный продукт с конкретным
> результатом; НИКАКИХ пустых страниц; рабочие промпты с переменными `[...]` + «что вставить / что получить»
> + уровни (Быстрый/Про/Advanced); реальный workflow, не «магия одним промптом»; блоки пример и плохо/хорошо;
> ACTION BLOCK «Сделай сейчас» + QUALITY CHECK; **мост в курс адаптирован под тему** (не копипаст CTA);
> **обязателен финальный блок «Путь в команду AlovLab»** (сильным студентам — реальные проекты/портфолио,
> корректно, без гарантий трудоустройства); актуальные модели — проверять, не выдумывать. Каркас — §29 правила.
> Связка карусель+Reels+методичка строится из ОДНОЙ CORE IDEA (§33).

Так собрана эталонная методичка `higgsfield-restaurant-reel` (v2). Все новые методички —
по этой системе. Полные правила и пайплайн: `content/guides/README.md`, скрипты-эталон
`scripts/guide_pdf_v2_build.py` (+ `scripts/guide_pdf_v2_shoot.js`).

Коротко, что нельзя нарушать:

1. **Фиксированные A4-страницы** (`div.page` 210×297мм, `overflow:hidden`, `page-break`) —
   раскладка по страницам вручную, полный контроль пагинации. Не собирать PDF из непрерывного HTML.
2. **Светлая основа для чтения**, тёмные плашки только под обложку и промпты. Не делать всё тёмным.
3. **Поля** ≥ 19мм верх/низ, ≥ 22мм бока; колонка ≤ ~150мм. **Тело 11pt / 1.62.**
4. **Один экран — одна мысль.** Лучше больше воздушных страниц, чем перегруженные.
5. **Карточки вместо тесных таблиц.** Промпт — тёмная плашка, метка «СКОПИРОВАТЬ», один промпт = одна страница.
6. **Колонтитулы + номера страниц + Содержание.** Врезки «Что должно получиться» / «Проверь себя», good/bad, схемы.
7. **Логотип** — на обложке и в финале; финал — контакты Telegram / VK / alovlab.ru.
8. **Проверка по готовому PDF:** отрендерить КАЖДУЮ страницу в PNG и открыть глазами; любой критерий < 8/10 → ещё цикл.

Жёсткие правила (применять ко всем текущим и будущим каруселям):

1. **Показ по карточкам.** После общего обзора показать каждый слайд отдельно, в полном размере,
   по порядку 1→6.
2. **Экспорт** — каждый слайд отдельным PNG, **1080×1350 (4:5), sRGB**, имена `slide-01.png … slide-06.png`,
   папка `exports/carousels/<бизнес>/`. Без браузерной рамки и служебных зон.
3. **Аудит по готовому PNG**, а не по коду: текст не обрезан, пустые зоны — осознанный воздух
   (блоки растянуты на всю высоту), читаемо на телефоне, стиль единый. Первый слайд жёстче
   (хук + визуальный конфликт + интрига); слабее 8.5/10 — не готово.
4. **Футер НЕ пишем.** На слайдах карусели нет «Автоконтент 2026 / t.me/AlovLab».
5. **Логотип** — только настоящий знак `assets/img/logo-mark.png`, «AlovLab» слитно.
6. **Честность.** Кадры — концепт-дизайн, не «результат клиента». Реальные фото вшиваются через
   `photos`-слоты (файлы в `content/carousel-assets/<бизнес>/`). Выдуманных цифр нет; цена студии
   не называется.
7. **Никогда** не заканчивать словами «карусель готова», показав только страницу в браузере —
   готово = отдельные PNG + визуальная проверка каждого + разбор + предложение следующей правки.
8. **Основной визуальный стиль — «showcase»** (стеклянный орб/иконка, свечение, кольца, искры,
   градиентный uppercase-заголовок белое+оранжевое, лого с подчёркиванием). Сборщик-эталон
   `scripts/carousel_showcase_render.py`. Флет-стиль — для образовательных на примерах.
   Язык — русский, латиница только в подписи **AlovLab** и в самих промптах (EN).
9. **В каждой карусели ОБЯЗАТЕЛЬНО:** (а) примеры пользы — на чём применимо и для какого бизнеса;
   (б) готовые **промпты**. Где уместно — рисунок темы + метки «Нейросеть» и «Бизнес» на слайде
   (эталон — `scripts/carousel_showcase_prompts.py`).

## Приложение Г. Reels / HeyGen / Seedance (жёсткое правило)

При сборке Reels через HeyGen **всегда разделяй сцены** на `avatar_scene` и `non_avatar_scene`.

**Сцена без аватара ОБЯЗАТЕЛЬНО генерируется через Seedance внутри HeyGen** как отдельная
motion-scene. Запрещено заменять такую сцену:
- статичной картинкой;
- screenshot;
- overlay-плашкой;
- slideshow;
- простым zoom изображения;
- текстом поверх фона.

Для `non_avatar_scene` **всегда описывай действие**: что появляется, двигается, печатается,
подсвечивается, включается, вибрирует, трансформируется. **UI оживает внутри устройства:**
уведомление — внутри телефона, typing — внутри Claude, интерфейс — внутри ноутбука.

На `avatar_scene` никакой текст, UI или графика **не перекрывают лицо, глаза или рот** аватара.
На сценах с читаемым UI и схемами **субтитры отключать** либо выносить в безопасную зону без
пересечения с текстом сцены.

В инструкции HeyGen обязательно писать дословно:
> **“Generate all non-avatar scenes with Seedance inside HeyGen. Do not use static overlays,
> screenshots or slideshow-style animation.”**

**Проверка перед финалом:** если сцена без аватара выглядит как слайд, статичная картинка или
overlay — сцена бракованная и должна быть перегенерирована через Seedance.
