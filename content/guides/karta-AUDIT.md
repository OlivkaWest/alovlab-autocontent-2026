## 3. Десять самых слабых мест
1. Всего 2 промпта — это не «работа с Claude», а две команды.
2. Нет **Prompt Stack** (диагностика → трение → убеждения → доказательство → последовательность → генерация → red-team → humanize → score).
3. Нет раздела **Prompt Debugging** — что делать, когда Claude выдал ерунду.
4. Нет **before/after цепочек** (вход → плохой промпт → плохой ответ → диагноз → лучше → почему).
5. Framework беден: 3 поля (Состояние/Трение/Сдвиг). Нет ДОКАЗАТЕЛЬСТВА и ДЕЙСТВИЯ — а без них касание не закрывается.
6. Примеры-посты «идеальные», без разбора, почему именно так; нет «что было бы плохо».
7. Стр. 3 (диагноз) и стр. 4 (принципы) дублируют мысль «сначала диагностика» — merge.
8. Стр. 6 (анатомия) и стр. 11 (как строить) частично повторяют framework — сжать.
9. Нет «как дожать Claude» / follow-up после каждого промпта.
10. Практики нет: бланк есть, но нет сквозного задания, которое доводит до готовой серии постов.

## 4. Десять сильных мест (сохранить/усилить)

4. Промпт с остановкой «жди ок» (итерация) — хорошая архитектурная деталь. 5. Разбивка на 4 касания.
6. Примеры в честной нише (ИИ/контент). 7. Чистая типографика/воздух. 8. Бланк для заполнения.
9. Честность (Rule 0). 10. Связка с каруселью/рилом (единый метод).

## 12. Новая архитектура методички (mini-course)
Проблема → почему обычный подход мусор → FRAMEWORK (Карта состояний, 5 полей) → диагностика по полям → Prompt Stack (9) →
каждый промпт с обучающей обёрткой → Prompt Debugging → 3 before/after → сквозное практическое задание (артефакт) → бланк →
checklist → Master Workflow → следующий шаг. ~26–30 стр. Логика обучения, не число страниц.

## 13. Новый PROMPT STACK (9)
P1 ДИАГНОЗ (состояние аудитории) · P2 ТРЕНИЕ (истинный барьер) · P3 УБЕЖДЕНИЯ/ВОЗРАЖЕНИЯ · P4 ДОКАЗАТЕЛЬСТВО (что снимет
сомнение) · P5 ПОСЛЕДОВАТЕЛЬНОСТЬ (порядок 4 касаний) · P6 ГЕНЕРАЦИЯ (посты по карте) · P7 RED TEAM (разнести свой результат) ·
P8 HUMANIZE (убрать AI-язык) · P9 SCORE (оценить по критериям). Каждый — отдельная работа, вход одного = выход предыдущего.

## 14. Три примера старый → новый (принцип)
1. Промпт: было «Собери серию прогрева из 4 постов» → стало P1–P6 стек с диагностикой и остановками.
2. Пример: было «идеальный пост» → стало вход → плохой промпт → плохой ответ → диагноз → лучший промпт → лучший ответ → почему.
3. Framework: было 3 поля → стало 5 (добавлены Доказательство и Действие — касание закрывается).

## 15. Почему новая версия сильнее
Учит мыслить и управлять Claude (стек + отладка + red-team), а не копировать команду. Даёт механизм починки плохого ответа.
Доводит до готового артефакта (серия постов). Framework принимает решения (5 полей = 5 вопросов). Каждая SAVE-страница автономна.
