# AlovLab · Октябрь 2026 · G01 «Промпт-помощник для работы» (дни 1–3)

## Глава 1 · Голосовое → сценарий
Для кого: авторы и фрилансеры, которым легче объяснить голосом, чем написать. Результат: черновик
поста из голосового сообщения за 5 минут. Время: 5–10 минут. Уровень: базовый.

Метод: расшифровка голосового — сырьё, не готовый текст. Промпт не переписывает её красиво, а
собирает в структуру поста, сохраняя формулировки автора.

**Шаблон промпта:**
```
Вот расшифровка моего голосового сообщения: [вставить текст расшифровки].
Собери из неё сценарий поста: хук в первой строке, основная мысль, один пример, один призыв.
Сохрани мои формулировки и порядок мыслей, где это возможно. Не заменяй мою речь на гладкий обобщённый текст.
Если где-то мысль оборвана — оставь пометку [уточнить], не додумывай за меня.
```
Что должно получиться: черновик, который узнаваем как свой, а не как версия нейросети.

## Глава 2 · Структура промпта: роль, контекст, ограничения, формат
Для кого: те, кто пишет клиентам/партнёрам через ИИ. Результат: свой промпт-каркас для
повторяющейся переписки.

- **Роль** — кто ты в этой задаче? Пример: «Я фрилансер-дизайнер, пишу владельцу кофейни».
- **Контекст** — что адресат знает/не знает? Пример: «Видел работы в Instagram, не знает цен».
- **Ограничения** — что нельзя? Пример: «Не длиннее 150 слов, без канцелярита».
- **Формат** — как должен выглядеть результат? Пример: «3 абзаца + один следующий шаг».

**Шаблон:**
```
Я [роль], пишу [кому и зачем].
[Что адресат уже знает / не знает].
[Ограничения по длине/тону/что не упоминать].
Формат: [структура результата].
```
До/после: «напиши предложение клиенту» без структуры даёт обобщённый текст; та же задача со
структурой — текст с деталями конкретного клиента.

## Глава 3 · Как проверить ответ ИИ
Для кого: любой, кто использует ответы ИИ в реальной работе. Результат: привычка проверять перед
использованием.

Три проверки: 1) первоисточник — открой сам, не верь пересказу; 2) одно конкретное утверждение —
проверь именно его; 3) цифры — отдельно, по независимому источнику.

Так нельзя: переспрашивать ту же модель (тот же источник, не проверка); требовать «скрытые
рассуждения» как доказательство (достаточно проверяемых шагов и источника).

**Чек-лист:**
```
Перед тем как использовать этот ответ:
1) Есть ли первоисточник? Открыл его сам?
2) Какое одно утверждение здесь ключевое? Проверил его отдельно?
3) Есть ли цифры? Сверил их с независимым источником?
Если хотя бы один пункт не выполнен — не использую ответ как факт, использую как черновик.
```

## Частые ошибки
1. Глава 1: просишь «сделай красиво» вместо «сохрани мою речь» — получаешь обобщённый текст.
2. Глава 2: указываешь только роль без контекста и ограничений — ответ остаётся обобщённым.
3. Глава 3: переспрашиваешь ту же модель вместо независимой проверки.

## Сделай сейчас
- Возьми реальное голосовое, преврати в черновик по шаблону главы 1.
- Собери свой промпт-каркас по формуле главы 2.
- Прогони любой рабочий ответ ИИ через три проверки главы 3.

**Самопроверка:**
- [ ] Черновик из голосового звучит как я, не как нейросеть.
- [ ] Промпт-каркас заполнен под конкретную свою переписку.
- [ ] Хотя бы один ответ прошёл все три проверки перед использованием.

## Источники и статус проверки
Методология глав — общий принцип промпт-инжиниринга, не привязан к версии продукта. Конкретные
названия пунктов интерфейса для расшифровки голосовых — не проверялись напрямую. Оба примера
(главы 1 и 2) — учебные, не результат реального клиентского проекта.
