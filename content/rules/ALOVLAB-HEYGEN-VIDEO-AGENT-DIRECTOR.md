## 0. Главное правило

Основная площадка генерации Reels — **HeyGen Video Agent**: получает подробное режиссёрское
задание и сам создаёт ролик (сценарий→сцены→визуал→монтаж→субтитры), а не просто произносит текст
одним аватаром. Claude Code отвечает за исследование темы, сценарий, диалоги, режиссёрскую
концепцию, раскадровку, задания для Seedance внутри HeyGen, систему визуальных вставок, монтажную
драматургию, синхронизацию графики и речи, субтитры и точную инструкцию для Video Agent. Основной
результат — **один полный, готовый к вставке в HeyGen Video Agent master-промпт**, не набор идей
или отдельных промптов Seedance по частям.

## 1. Честная проверка актуальных функций HeyGen (27.10.2026)

Прямой доступ к `help.heygen.com` заблокирован сетевой политикой этой среды (та же ситуация, что
ранее с `docs.heygen.com`/`developers.heygen.com`) — WebFetch на все три присланные ссылки вернул
`ENOTFOUND`. Ниже — вторичное подтверждение через WebSearch (не первоисточник), с честной пометкой,
где источники официальные (сниппеты help.heygen.com/heygen.com в выдаче), а где сторонние. Перед
реальной сборкой сверяйте с живым интерфейсом HeyGen на момент работы — функции могли измениться.

- **Video Agent** — верхний уровень стека: по одному промпту строит мультисценовое видео (скрипт,
  A-roll, B-roll, motion graphics, нарратив, субтитры), показывает план (Video Plan) на согласование
  до генерации, дорабатывается диалогом в чате. Промпт может быть: короткой идеей, **полным
  вставленным сценарием** (это прямо названо главным усилением точности — агент следует ему по
  сценам, улучшая темп/визуал), или таймкодированным шот-листом («00-05 секунд: аватар
  представляет...» — ближайший аналог раскадровки). Хронометраж — ориентир, не жёсткий лимит. Чтобы
  обойтись без аватара, это нужно прямо указать в промпте («no avatar») — иначе аватар предполагается
  по умолчанию.
- **AI Studio** — это редактор, не отдельный режим генерации: проект, собранный Video Agent, остаётся
  редактируемым в AI Studio (текст, тайминг, раскладка, цвет).
- **Presenter Mode** — один из двух режимов Single Scene для анимации Photo Avatar, на базе Avatar IV,
  аватар смотрит прямо в камеру — когда в фокусе речь и естественная подача.
  **Cinematic Mode** — второй режим Single Scene, на базе Seedance, больше контроля над движением,
  исполнением, поведением камеры (на части тарифов — только Pro).
- **Avatar Shots powered by Seedance 2.0** — отдельная функция (своя страница в help-центре,
  `articles/14448006`), не то же самое, что Video Agent: до **трёх аватаров в одном сгенерированном
  кадре одновременно**, порядок реплик задаётся в промпте, поддерживает кинематографичную раскадровку
  (общий план → смена планов между говорящими), явный операторский язык даёт точный результат («slow
  dolly-in», «crane shot overhead», «tracking shot from the right») — расплывчатое «cinematic» почти
  не влияет. Доступно на платных тарифах; 15-секундный ролик — 60 или 150 кредитов (720p/1080p), 4K
  пока недоступен. Seedance не допускает человеческие лица в публичном API — появление реального лица
  в кадре возможно только через собственную верифицированную инфраструктуру HeyGen (Digital Twin), то
  есть и второй аватар должен быть реальным верифицированным аватаром пользователя, не сгенерированным
  с нуля.
- **Поддерживает ли сам Video Agent нативно несколько аватаров в одной сцене** — честно: не
  подтверждено однозначно. На маркетинговой странице Video Agent есть пример промпта на 45-секундный
  скетч с двумя аватарами в диалоге, что намекает на поддержку, но ни один источник не называет явный
  лимит или механизм внутри самого Video Agent. Задокументированный механизм многоаватарности —
  именно **Avatar Shots**. Отсюда — два рабочих маршрута для режима с двумя аватарами (§5 ниже).

## 2. Распределение обязанностей

**Claude Code:** думает, исследует, пишет, проверяет, проектирует визуал, готовит полное техническое
задание. **HeyGen Video Agent:** получает сценарий, формирует Video Plan, использует выбранный
аватар и голос, подбирает/генерирует визуал, монтирует, работает с переходами/графикой/субтитрами,
создаёт итоговый ролик. **Пользователь:** открывает Video Agent → выбирает существующий аватар →
выбирает свой голос → вертикальный формат → включает Seedance, где предусмотрено сценарием →
вставляет промпт Claude → прикладывает референсы → проверяет Video Plan → запускает генерацию. Не
переписывает сценарий и не додумывает кадры вручную.

## 3. Аватар и голос — неизменяемое правило

Никогда не создавать нового аватара или голоса, не подменять внешность пользователя, не запрашивать
и не придумывать ID, не предлагать другого диктора, не использовать случайный голос из каталога, не
пересоздавать лицо по текстовому описанию. Внутри master-промпта — дословно:
> "Use the avatar and voice already selected by the user in HeyGen. Do not replace, recreate, or
> substitute either one."

Эта строка — только в разделе AVATAR/VOICE master-промпта, никогда не в произносимом тексте.

## 4. Стиль речи

Полностью по `GLOBAL-REELS-VOICE-RULE.md` (живая разговорная речь, единый список запрещённых фраз
§3-4, запрет тире §8, структура озвучки). Дополнительный акцент из этого промпта: подача уверенная,
современная, с лёгкой уместной иронией и сленгом — без пафоса и без сленга ради сленга. Пример
плохой/хорошей реплики — см. голосовой стандарт, не дублируется здесь второй раз.

## 5. Два режима

**`/reel`** — один аватар (по умолчанию). Хук → проблема → поворот → демонстрация → payoff → CTA.

**`/reel-duo`** — два утверждённых аватара проекта. Главное ограничение не снято этим документом:
**паспорт второго (женского) аватара в проекте по-прежнему не утверждён** (`ALOVLAB-REELS-DIRECTOR-
STANDARD.md` §3) — Claude не придумывает его внешность/имя/голос ни при каком техническом маршруте
ниже. Как только второй аватар появится в HeyGen-аккаунте пользователя, предложить один из двух
маршрутов (честно сверить с живым интерфейсом перед использованием — §1 выше не окончательная истина):
1. **Avatar Shots powered by Seedance 2.0** — если на момент сборки подтверждено, что это доступно
   внутри используемого workflow Video Agent: до 3 аватаров в одном кадре, порядок реплик в промпте,
   операторские планы между говорящими.
2. **Сцена за сценой** (гарантированно работает всегда) — каждый аватар озвучивается в своей сцене
   по очереди, монтажная сборка объединяет их (тот же подход, что уже отработан в
   `content/october-2026-system/reels-extra/day-19/ru/06_HOST_B_SCRIPT.txt`). Выбирать этот маршрут,
   если Avatar Shots на момент сборки не подтверждается в используемом интерфейсе.

Правило диалога-конфликта (не вопрос-ответ, а конфликт мнений, тест на перестановку реплик, аудит
из 10 пунктов) — без изменений, см. `ALOVLAB-REELS-DIRECTOR-STANDARD.md` §4-5, §14.

## 6. Драматургия

30-45 сек (до 60 для сложных тем, не растягивать искусственно). HOOK (1-3 сек: конфликт, парадокс,
неожиданная фраза, сильный визуальный образ, демонстрация результата — не логотип и не приветствие)
→ PROBLEM (конкретная проблема человека) → TURN (неожиданное решение/смена взгляда) →
DEMONSTRATION (практическое действие, инструмент, результат) → PAYOFF (закрывает обещание хука) →
CTA (одно естественное действие, только если реально нужно).

## 7. Визуальная философия

Не «говорящая голова + случайные вставки». Каждый кадр объясняет, усиливает или доказывает
произнесённую мысль — аватар рассказывает, визуал показывает. Если реплика называет конкретный
результат/действие/поле интерфейса — на экране должно быть именно оно, не абстрактный «цифровой
мозг» или случайный сервер.

## 8. Seedance внутри HeyGen

Выбирать Seedance (Avatar Shots / Cinematic Mode) для: реалистичных действий, нестандартных
локаций, драматичных метафор, движения камеры, продуктовых сцен, кинематографичной демонстрации —
**не автоматически для всего ролика**. Реальный интерфейс Claude/ChatGPT — настоящий скринкаст, не
Seedance-имитация. Таблицу — motion graphics. Последовательность — схема. Операторский язык —
конкретный, не «cinematic» вообще (по исследованию §1: «slow dolly-in», «crane shot overhead»,
«tracking shot from the right» — так, а не абстрактно).

Для каждой Seedance-сцены — полный набор полей:
`SUBJECT · ACTION · ENVIRONMENT · CAMERA ANGLE · CAMERA MOVEMENT · LIGHTING · ATMOSPHERE ·
VISUAL STYLE · DURATION · CONTINUITY · NEGATIVE CONSTRAINTS`. Сцена — под конкретную реплику, не
отвлекающий B-roll без смысловой причины.

## 9. Референсы

Перед сценарием — разобрать всё реально приложенное (не то, что упоминалось раньше в переписке).
Каждому файлу — назначение одной строкой: `PHOTO_01: эталон внешности`, `SCREEN_03: настоящий
интерфейс Claude`, `LOGO_05: утверждённый знак` и т.п. Не смешивать назначения. Не перерисовывать
реальный интерфейс, когда есть настоящий скриншот. Не использовать чужое фото как источник
внешности пользователя. Если референсов нет — проектировать с доступными средствами, не выдумывая
реальные данные (та же честность, что в `ALOVLAB-HEYGEN-REELS-STANDARD-v2.md` §5/§6).

## 10. Визуальный стандарт AlovLab

Премиальная кинематографичная подача, реалистичные кадры, чёткая композиция, контролируемый свет,
чистая работа камеры, современная типографика, фирменный оранжевый акцент, графитовые/светлые
нейтральные тона (совместимо с CLAUDE.md §9). Запрещено: дешёвый киберпанк ради красоты, летающие
интерфейсы без логики, случайные неоновые линии, постоянная тряска, шаблонные вспышки, гигантские
заголовки поверх изображения, лишние подписи, несуществующие интерфейсы под видом настоящих,
альтернативные версии логотипа AlovLab (только загруженный оригинальный файл
`assets/img/logo-mark.png`).

## 11. Текст и графика на экране

Синхронизация с произносимым словом в момент его звучания (пример: «сначала контекст» → подсвечен
CONTEXT, «потом задача» → TASK, «и формат ответа» → OUTPUT). Оранжевый акцент AlovLab. Не
подсвечивать всё разом, не дублировать одну мысль тремя блоками текста. Если на экране промпт или
интерфейс — субтитры не перекрывают его (то же правило «один текстовый фокус», что в
`ALOVLAB-REELS-DIRECTOR-STANDARD.md` §11).

## 12. Субтитры

Не обязательны во всех сценах. Полезны на сценах с аватаром. Могут мешать на сценах с интерфейсом/
промптом/таблицей/схемой — для каждой сцены явно указывать `SUBTITLES: ON` или `OFF`. Не накладывать
автосубтитры поверх уже существующих надписей, без чрезмерной покадровой анимации слов. Проверять
кириллицу, орфографию, расположение.

## 13. Музыка и звук

Поддерживает ролик, не конкурирует с голосом. По умолчанию не использовать: дешёвую трейлерную
музыку, whoosh на каждой склейке, постоянные удары, банальные корпоративные мелодии, случайные
популярные треки. Технологичная тема — тонкая электронная атмосфера; ироничная — звук поддерживает
комедийный ритм; кинематографичная — динамика и паузы. Голос должен быть разборчив от первого до
последнего слова.

## 14. Структура master-промпта (обязательна для каждого /reel и /reel-duo)

Шаблон — `templates/heygen-video-agent-master.md`. Разделы: `PROJECT · FORMAT · AVATAR · VOICE ·
CREATIVE DIRECTION · VISUAL LANGUAGE · STORYBOARD · EXACT SPOKEN SCRIPT · GENERATED VISUALS ·
ATTACHMENTS · MOTION GRAPHICS · SUBTITLES · AUDIO · EDITING · FINAL FRAME · QUALITY CONSTRAINTS`.
Каждый раздел заполняется предметно по теме текущего выпуска — никаких абстракций вроде «добавь
красивые кадры» или «сделай вирусно»: только конкретное действие, изображение и его функция.

## 15. Шаблон сцены

Шаблон — `templates/heygen-scene.md`. Поля: `SCENE NN · TIME · PURPOSE · SHOT TYPE · SPEAKER ·
SPOKEN LINE · VISUAL · ON-SCREEN TEXT · SUBTITLES · TRANSITION` (+ `MOTION GRAPHICS`, если есть
подсветка интерфейса). В финальном промпте — только реальные реплики текущего выпуска, не примеры
из этого документа.

## 16. Проверка Video Plan

Шаблон — `templates/heygen-video-plan-review.md`, 12 пунктов: аватар сохранён · голос сохранён ·
реплики совпадают со сценарием · русский язык сохранён · порядок сцен верный · нет случайных
персонажей · визуал соответствует смыслу · референсы используются по назначению · нет случайного
стокового видео · субтитры не перегружены · Seedance решает нужную визуальную задачу · хронометраж
не изменился. Несоответствие — сформировать корректирующее сообщение, не запускать платную
генерацию заведомо неверного плана.

## 17. Правки после генерации

Шаблон — `templates/heygen-local-fix.md`. На конкретную жалобу («на 7 секунде субтитры перекрывают
промпт», «на 12 секунде чужой человек», «пятый кадр дешёвый») — точная команда на правку именно
этой сцены, не пересборка всего ролика. Если точнее исправить в AI Studio — сказать это прямо.

## 18. Формат ответа Claude на /reel и /reel-duo

1. **Краткая концепция** — название, тема, конфликт, ценность, длительность.
2. **Полный master-промпт** — один цельный текст, готовый для копирования прямо в Video Agent. Это
   основной результат, не разбивать на отдельные пять заданий.
3. **Материалы для загрузки** — список референсов, если они реально нужны.
4. **Проверка Video Plan** — 5-7 важнейших пунктов из §16 под конкретный выпуск.
5. **Готовая команда для корректировки** — короткое универсальное сообщение:
> "Keep the selected avatar, selected voice, approved Russian dialogue, and scene order unchanged.
> Refine only the scenes that do not match the approved storyboard. Preserve the AlovLab visual
> style, use relevant visuals, and avoid unnecessary subtitles or stock footage."
