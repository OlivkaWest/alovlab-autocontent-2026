# AlovLab HeyGen Director — живая речь и два аватара

Полное правило — `content/rules/ALOVLAB-REELS-DIRECTOR-STANDARD.md`. Дополняет
`content/rules/GLOBAL-REELS-VOICE-RULE.md` (голос, запрет тире, запрещённые фразы) и
`content/rules/ALOVLAB-HEYGEN-REELS-STANDARD-v2.md` (сцены, файлы пакета, §7 — аватар/голос не
выбираются Claude никогда). Этот скилл — точка входа по командам, не замена ни одного из трёх
документов.

## Разделение зон ответственности (не дублировать другие скиллы)

- **Какую тему снимать, если день/тема не заданы** → `.claude/skills/alovlab-reels-today/SKILL.md`
  (`/alovlab-reels-today`, открытое честное исследование). Этот скилл такого поиска не делает.
- **Производство полного пакета дня по месячному плану** → `.claude/skills/alovlab-content-month/SKILL.md`.
- **Этот скилл** — как написать сам сценарий/диалог и собрать режиссёрский пакет под уже выбранную
  тему, в режиме одного или двух аватаров.

## Команды

- **`/reel [тема или дата]`** — режим A (один аватар, Нейромонах). Процесс не меняется относительно
  `ALOVLAB-HEYGEN-REELS-STANDARD-v2.md` — этот скилл добавляет только более живую разговорную планку
  (правило §1 нового стандарта).
- **`/reel-duo [тема]`** — режим B (два аватара, диалог-конфликт). **Перед запуском проверь, утверждён
  ли паспорт второго аватара** (реальный аватар + голос, уже настроенные в HeyGen проекта — см. §3
  стандарта). Если паспорта нет: выдать всё, кроме финального `01_HEYGEN_AGENT_PROMPT.txt`
  (диалог, режиссёрский сценарий, B-roll, субтитры, подсветка), и явно попросить пользователя
  назначить второй аватар+голос в HeyGen — не придумывать внешность/имя/Voice ID самостоятельно, не
  предлагать подбор в Higgsfield от своего имени.
- **`/dialogue-review [путь к сценарию]`** — прогнать текст через аудит §14 стандарта (10 вопросов),
  вернуть список конкретных правок построчно, не общую оценку «хорошо/плохо».
- **`/heygen-script [путь к утверждённому диалогу]`** — собрать `01_HEYGEN_AGENT_PROMPT.txt` и
  `02_SCENES.txt` из уже одобренного текста (не писать диалог заново на этом шаге).
- **`/seedance-broll [путь к сценарию]`** — промпты для B-roll по §10 стандарта (SUBJECT/ACTION/
  ENVIRONMENT/CAMERA/LIGHT/MOTION/DURATION/END FRAME/NEGATIVE CONSTRAINTS), с учётом подтверждённых
  возможностей текущей версии модели — не выдумывать параметры.
- **`/reel-from-plan`** — три темы из утверждённого `content/october-2026-system/calendar/calendar.csv`
  (не открытый веб-поиск), с HOOK/КОНФЛИКТ/ПРАКТИЧЕСКИЙ ПРИЁМ/HERO MOMENT/ПОЧЕМУ ИНТЕРЕСНО для
  каждой, рекомендовать сильнейшую. Если тема уже названа — не предлагать альтернативы.

## Как работать

1. Прочитать `ALOVLAB-REELS-DIRECTOR-STANDARD.md` целиком перед первым запуском в сессии (и
   `GLOBAL-REELS-VOICE-RULE.md` + `ALOVLAB-HEYGEN-REELS-STANDARD-v2.md`, если давно не перечитывались
   — правила меняются, не полагаться на память прошлой сессии).
2. Для `/reel-duo` — сначала проверить §3 (паспорт второго аватара), не писать реплики под
   выдуманную внешность.
3. Писать диалог целиком (весь разговор), потом резать по персонажам — не реплику за репликой с нуля
   под каждого отдельно.
4. Прогнать через аудит §14 перед выдачей — вслух, «я бы так реально сказал?».
5. Проверить запрет на тире (`GLOBAL-REELS-VOICE-RULE.md` §8) и полный список запрещённых фраз
   (там же §3-4, включая дополнение 21.10.2026) по всему тексту озвучки, для обоих персонажей.
6. Выдать все 14 пунктов формата §15 стандарта — не подменять сценарий кратким описанием.
